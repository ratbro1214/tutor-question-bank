# 数学题 AI 识别性能优化与验收记录

测试日期：2026-09-27（Asia/Shanghai）  
模型与接口：`grok-4.6`，Chat Completions，严格 JSON Schema  
数据集：`scripts/benchmark-analysis.mjs` 生成的 6 张可复现合成题图

## 调用链梳理

改造前：浏览器提交图片 → API 读取并转 Base64 → 视觉模型提取题干 → 文本模型分类 → 本地标签校验 → 冲突时再次完整文本分类 → 前端一次性得到结果后才出现表单。

改造后：原图立即预览并保留 → 浏览器按内容自适应裁白边/缩放识别副本 → API 读取一次并计算内容哈希 → 缓存查询 → 单次视觉识别同时完成题干提取和初步分类 → 本地标签规范化与校验 → 仅真实冲突或不完整时复用题干做纯文本复核 → 通过 NDJSON 状态流回填教师未修改的字段。

`taxonomy.ts` 和 `senior-taxonomy.ts` 仍是唯一标签来源；缓存键包含图片 SHA-256、学段、模型、推理强度、提示词版本和标签版本。教师确认结果继续单独保存，不写回 AI 缓存。

## 性能数据

最终 low 冷缓存结果：

| 指标 | 结果 |
| --- | ---: |
| 样本数 | 6 |
| 平均端到端耗时 | 19.624 s |
| P50 | 18.430 s |
| P95 | 36.875 s |
| 模型调用总数 | 7 |
| 输入 Token | 40,950 |
| 输出 Token（含推理） | 8,917 |
| 按 xAI 公布单价估算的整批成本 | 约 US$0.111（约 US$0.0185/题） |
| 命中预设主章节与关键知识点 | 6/6 |
| 标记教师复核 | 1/6（裁切异常题） |

5 个正常样本均为 1 次模型调用；裁切异常样本按需进行了第 2 次纯文本复核。各样本耗时依次为 11.412、12.315、18.430、19.347、19.364、36.875 秒。

同一批图片再次提交时全部命中结果缓存：平均 17.7 ms、P50 14.8 ms、P95 31.0 ms，模型调用 0，Token 0。

成本按本批 24,822 个非缓存输入 Token × US$2/百万、16,128 个缓存输入 Token × US$0.5/百万、8,917 个输出 Token × US$6/百万估算；若当前中转接口另有加价，应以其账单为准。

页面实测中，一张 1400×900 JPG 的浏览器预处理耗时 91 ms，识别副本变为 1370×870；后台识别期间教师输入未被 AI 返回覆盖。取消后原图、教师输入和重试入口均保留。

## 准确率与推理强度

low 初版在同一数据集命中 4/6。失败类型是二次函数最值漏标和高中多项式单调性误归一般函数。增加窄范围、可解释的本地规则后最终为 6/6，没有删除原有结构校验。

medium 的系统批测出现普通题超过 60 秒及上游内部错误，因此中止整批，不能给出有效 P50/P95；浏览器单例测试曾返回约 20.9、32.1 和 56.9 秒，波动明显。medium 保留为复杂题主动对照，不作为默认模式。

本项目改造前没有同一数据集和结构化计时记录，因此不能诚实给出“改造前平均耗时”。旧代码可确定普通题固定进行 2 次串行模型调用，最终代码普通题为 1 次；这里不把调用次数变化伪装成实测耗时提升。

## 测量字段与隐私

服务端记录上传/表单解析、图片读取、哈希和编码、模型首响应、模型完整响应、JSON 解析、本地校验、按需复核、总耗时及 Token。浏览器补充预处理和从点击识别到结果可编辑的总耗时。

日志只含随机分析 ID、学段、模型配置、耗时、Token、缓存/复核状态和校验错误代码，不记录 API Key、学生信息、文件名或完整题目。旧开发日志中存在改造前写入的完整分类对象，本次代码已停止继续产生此类日志；历史日志未自动删除，以免擅自清理用户数据。

## 复现

```powershell
npm run dev
$env:BENCHMARK_BASE_URL='http://127.0.0.1:5173'
npm run benchmark:analysis
npm run benchmark:analysis -- --medium
```

脚本覆盖普通文字题、复杂公式、横向长截图、手机拍摄效果、多知识点综合题和裁切异常。它报告逐题耗时、模型调用、Token、缓存状态、实际/预期标签以及汇总的平均值、P50、P95、分类通过率和复核率。
