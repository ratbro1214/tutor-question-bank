# 诊断闭环深化与验收

本轮落实研究方案的第一阶段：以 Agent4Edu 的画像、记忆和行动思路组织现有功能，先让真实作答、诊断与画像有可核对的联系。没有直接引入三个外部项目的运行框架。ClassroomSimulacra 风格的教师干预前后评测、OpenMAIC 风格的互动课堂，以及自动反思与策略实验留在后续阶段。

## 实现与使用

1. 在学生题目页记录错误或部分正确的真实作答；仅有最终答案也能保存，不必猜测具体错因。
2. 在学生页的教学智能体建议中生成两题诊断，经教师核验后采用。
3. 进入该题目页，选择“本次诊断题”，逐题保存真实作答、结果与完成方式。题目、目标作答和知识点自动绑定，保存后转到尚未记录的另一题。
4. 干预后检测或间隔复查可指定“要验证的原始作答”。不指定时仍保存事实，但不据此判断原错因改善。
5. 在画像、诊断队列和智能体建议展开“查看依据”，查看真实记录并跳转原始作答。已采用方案的历史入口和进度继续保留；导出包含关联信息。

两道诊断题都独立正确只意味着当前没有发现持续错误证据，不直接等同于掌握。模型诊断方案本身不进入学习证据。画像只有教师确认的具体错因及明确关联的后续检查才能改变状态；缺少证据会展示不确定项。

## 实测结果

- `npm test`：47 项通过，0 项失败。覆盖无关同知识点作答、两题关联、同题重试、后续答错、提示后正确、无关提问教学、复发后更新、真实证据引用和旧方案迁移。
- `node node_modules/typescript/bin/tsc --noEmit`：通过。
- 对修改的页面、学习/诊断逻辑、数据库和新验收脚本运行 ESLint：通过。
- `npm run build`：通过。Windows 首次重建因验收服务器占用构建目录失败，停止该服务器后重建成功。
- `scripts/test-diagnostic-links.ts`：通过。校验两题物化、草稿阻止作答、采用决定幂等与冲突、学生归属、阶段与时间、原错题关联、作答重试与内容冲突、两题完成和 XLSX 关联字段。
- `scripts/test-learning-api.ts`：通过。回归 AI/人工归档来源、原图与文本相似关联、教学记录、复查、幂等、学生隔离、导出日期和公式文本保护。
- 浏览器在隔离数据上保存第二道诊断的真实作答成功；时间线显示对应诊断题和验证目标；点击“查看原始作答”定位到该记录；完成后恢复普通作答入口。

以上为合成数据功能验收，不是模型准确率、教学收益或真实学生学习效果实验。本轮没有调用付费模型，诊断生成验收使用无密钥规则回退。

## 数据与运行

隔离验收配置通过 `node scripts/prepare-learning-fixture.mjs` 从构建配置生成，独立状态位于 `.test-runtime/evidence-fixture/state`。全部迁移只在该隔离状态初始化。服务器固定 `127.0.0.1:8789`，测试脚本要求 `LEARNING_TEST_URL=http://127.0.0.1:8789`；配置目录的 `.dev.vars` 使用空模型密钥，不复制用户凭据。执行两个脚本可用 `node node_modules/tsx/dist/cli.mjs scripts/脚本名.ts`。

用户本地数据库在停服后备份到 `.wrangler/backups/before-0010-20260930-184936/d1`，随后仅应用 `drizzle/0010_slippery_ultragirl.sql`，五条语句成功。旧题、方案和作答保留；旧作答的关联字段保持空值，不凭猜测回填。项目恢复运行于 `http://localhost:5173/`。

后续深化优先加入可回放的教学干预评测：以同一批学生状态和题目比较不同策略，明确教师正确决策的标注规则，记录改善判断错误率、证据完整率、教师耗时和模型成本，再决定是否扩展互动课堂。
