## 内容审核与来源边界

本数据是 AI 辅助独立编写的课程草案，所有节点和关系以 `source=seed`、`knowledge_review_status=pending` 导入，不伪称已经过教师审核。
参考资料记录了教育部课程标准发布通知，但并未逐条核对课程标准正文，因此不宣称完成官方课程标准的全面覆盖认证，也不冒充教材原文或真实高考题。

`difficulty`、`importance`、`exam_frequency` 暂为 null，留待教师根据课程目标与实际试卷样本评定；尤其不根据主观印象制造“高频”数据。
审核信息与正文可以在数据库维护后保留，当前阶段不提供审核 UI。正式图谱的 approved 过滤与审核服务按 Phase 3 实现。

## 校验及导入约定

节点 ID 来自数据版本与稳定编码，名称变化不改变 ID。逐一验证唯一编码、完整五层、相邻层级、单父节点、端点存在、同学科/学段/课程版本及非自环。
related 端点按 ID 排序，拒绝反向重复；contains 与 belongs_to 的镜像重复也会被拒绝。
prerequisite 与 advanced 统一换算为依赖方向后执行拓扑检查，避免混合关系产生隐藏环路。

导入使用 BEGIN IMMEDIATE 事务。相同种子身份仅跳过，不覆盖已修改正文、评级、审核状态或时间；遇到非本种子身份的编码/ID 冲突则整批回滚。
插入后对数据库中的合并图再验证，已有关系造成的多父节点或前置环路也会阻止导入。
这种保守幂等策略不会自动更新旧种子内容，也不会重新创建被改用其他身份的关系。数据修订需显式迁移或新版本，不应通过删库重导覆盖教师成果。
已有孤立候选节点可以保留；完整五层约束针对本次种子，而不是强制所有待审核候选已经拥有父节点。

## 使用方法

在项目根目录执行，环境遵循 E 盘缓存偏好。

```powershell
. 'E:\AI\environment.ps1'
# 只读校验，不启动服务也不写数据库
node --import tsx scripts/knowledge-catalog.ts --validate

# 新建独立预览库，执行迁移并重复导入验证
node --import tsx scripts/knowledge-catalog.ts --preview

# 相关测试
node --import tsx --test tests/knowledge-catalog-seed.test.ts tests/knowledge-catalog-schema.test.ts
```

预览库位于当前工作目录的 `work/knowledge-graph-phase2/<运行编号>/`；报告、JSON 副本和章节清单位于 `outputs/knowledge-graph-phase2/<运行编号>/`。

离线业务导入使用 `--database <已核实的项目内SQLite绝对路径>`，要求数据库已存在、统一题库前置表已存在，且项目服务已停止。命令复用项目进程检查，不会停止用户服务；先将数据库备份到本次 outputs 目录，再按需执行 0023 迁移及导入。
0023 建表迁移和种子导入是各自独立事务；种子失败会回滚种子写入，但已成功创建的空表会保留。脚本不修改 Drizzle 迁移执行历史，沿用项目已有离线 SQL 应用方式，不能与另一个迁移执行器无检查地混用。
该适配器仅用于本地 SQLite，不能直接导入 Cloudflare Worker API；后续在线服务须使用 D1 适配器。
