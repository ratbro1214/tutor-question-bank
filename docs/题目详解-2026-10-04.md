# 题目详解与教师备课

题目详情页在原图下方提供独立的“题目详解”，展示最终答案、解题思路、分步推导、老师怎么讲、易错点，以及可展开的结果核验和另一种解法。

## 使用

1. 打开学生的一道题，核对解析对应的题目原文。可修正识别错误；修改仅作为本解析的题干保存。
2. 点击“生成题目详解”。服务使用项目当前的模型配置，同时读取原图和题干；不发送学生姓名或学习记录。
3. 阅读生成结果，必要时点击“修改解析”，逐步修改或增删步骤；也可以直接手工填写。
4. 生成成功后立即自动保存到数据库。手工修改在内容完整后自动保存；未完成编辑保留在本机草稿。教师核对题目条件、答案和步骤后，可勾选确认，仍可点击“保存解析”立即保存。任何内容修改都会撤回已核对标记。
5. 已保存解析在再次打开题目时读取。重新生成失败或取消时，已有内容保留。

## 数学公式排版

新生成的解析使用 LaTeX 数学表达，行内公式用 `$...$`，独立推导用 `$$...$$`，浏览时由本地 KaTeX 排版。明确保留分子分母、复合指数范围、上下标、希腊字母、绝对值及导数。编辑与保存保留原始公式字符串，预览显示排版结果；数学字体由项目本地打包，不依赖外部 CDN。

历史纯文本解析只在显示时转换明确的 Unicode 上下标与原子分式，不改写数据库，不猜测旧文本中缺失的复合指数括号。无法解析的公式保留原文，避免吞字。渲染禁用可信 HTML、外部链接和图片命令，限制宏展开，并包含辅助阅读 MathML。

新增四个测试覆盖混合文本与公式原文往返、复合指数和分式排版、历史内容兼容、模型统一双重转义兼容、矩阵换行保留、损坏公式回退及 HTML 注入防护。显示层兼容重复转义，不修改保存的公式源码。

本机题目 #3 实际生成新版公式草稿，138.3 秒返回 200；浏览器核对了分式、导数、极限及希腊字母排版。该测试草稿生成时出现一处 `ln 4` 与 `17/16` 比较方向写反，已在预览草稿中人工修正；未自动保存或标记教师已核对。格式排版与数学内容正确性分别核验。

后续针对用户截图补充显示兼容：用逐段扫描替换公式定界符的整体正则配对，避免错位 `$`/`$$` 把中文与下一段推导吞成一个公式；识别独立的 `aligned` 等环境、多行行内公式及明确的裸 LaTeX 表达。显示层移除公式中的异常控制字符及其 `\\u007f` 等文本表示，兼容错配结束标记，同时保留原始输入和保存内容。新生成提示统一使用 `\\(...\\)`、`\\[...\\]`，要求开始、结束标记成对出现，减少美元符号错配。

截图复现用例在浏览器中验证，错位标记和异常字符不再显示，aligned 推导和双曲函数分式正常排版；另覆盖双重转义的括号定界符和环境。71 项测试、TypeScript 检查及生产构建通过。浏览器测试未保存，并在验证后恢复了原始草稿。损坏且无法可靠修复的表达仍保留原文，不推测数学含义。

条件不完整的模型结果会展示需要补充的信息；该状态不允许保存为已核对解析。格式校验只能保证结构完整，数学正确性仍需教师核验。结果核验段落来自模型，不能作为独立外部验证的证明。

## 数据和接口

- `question_explanations` 独立保存解析 JSON、对应题干、版本号、AI/人工来源、模型名称、教师核对状态和更新时间。解析不修改题目分类或学生学习画像。
- `GET /api/questions/[id]/explanation?studentId=…` 读取解析。
- `POST /api/questions/[id]/explanation` 根据原图和题干生成并自动保存，返回 `explanation`（版本号、核对状态、更新时间）。`expectedRevision` 防止慢生成覆盖其他页面的新修改。
- `PUT /api/questions/[id]/explanation` 显式保存，携带 `expectedRevision`。
- 所有接口核对题目与学生归属，并排除已删除题目和学生。原子版本检查拒绝另一页面的过期写入，保留当前输入。
- 新增迁移 `drizzle/0012_past_northstar.sql`，仅新增解析表。已有数据库先备份，再应用尚未执行的迁移。迁移前的本机备份在忽略的 `work/backups/`。

## 生成超时修复

2026-10-04，本机题目 #3 的日志显示 POST 在 120.0 秒返回 502，与旧版固定 120 秒中止设置一致。模型已经是 `gpt-6.1-sol`，切换模型没有改变这个时限。该记录无法区分上游排队与模型生成各自耗时。

Responses 请求改为 `stream: true`，服务器接收 SSE，仅在 `response.completed` 后校验完整解析；提前断流、失败及不完整事件不会作为答案显示。兼容返回普通 JSON 的上游及原有 Chat Completions 协议。整次请求（包含响应读取）最多等待 300 秒，主动取消与超时分别提示，生成失败保留教师原有内容。保留 medium 推理设置和原图核对。日志仅记录模型、耗时及取消/超时状态，不记录密钥、题干或图片。

同一道函数零点题连同原图实测：直接流式调用 68.8 秒完成；项目 POST 接口 70.3 秒返回 200，返回模型 `gpt-6.1-sol`，包含答案、步骤和讲解建议。测试结果留在忽略的 `work/`，没有自动保存到题库。此次成功不能保证上游以后每次都能及时响应。
