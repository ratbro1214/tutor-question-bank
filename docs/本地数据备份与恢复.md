# 本地业务数据备份基线

`.wrangler/state` 是本机开发的业务持久化目录，未经完整备份与校验不得删除。Git 忽略不表示它可丢弃。

| 资产 | 性质 | 删除影响 |
|---|---|---|
| `.wrangler/state/v3/d1` | 学生、题目、教师分类、教学记录、解析及英语实库 | 没有备份时无法保证恢复，Git 不保存这些记录 |
| `.wrangler/state/v3/r2` | 用户上传原图、试卷、裁切图及对象映射 | 缺对象或映射都会造成业务文件不可读取；不能只备份D1 |
| `data/english` | 原材料清单、规范语料、人工修正及派生词汇/练习 | 派生部分可重新生成，但人工修正、来源清单不能假设能重建，完整备份 |
| `public/english*` | 英语静态原始资料、来源截图、PDF及图片 | 属于应选择纳入版本控制的资料；当前很多未跟踪，外部链接不保证永久有效，完整备份 |
| 根目录 `blobs` | 当前来源/用途未明确的二进制资产 | 暂不认定为缓存，额外备份并保留，不删除 |
| `db`、`drizzle`、`.openai/hosting.json`等 | 代码仓库的schema、迁移及非密钥绑定元数据 | Git可能只保留已提交版本；备份当前版本用于解释数据状态 |
| `.wrangler/state/v3/cache` | AI结果缓存 | 可以重新计算，但会产生请求费用；不纳入业务备份 |
| `.next`、`.vinext`、`dist`、`node_modules`、临时文件 | 构建/依赖/运行工具产物 | 可重新生成；不纳入业务备份 |
| 浏览器localStorage详解草稿 | 尚未完成的编辑 | 不属于磁盘项目备份，关闭/清理浏览器前应完成保存或手动导出 |

## 备份

在仓库目录使用支持 `node:sqlite` 及 SQLite Backup API 的现有 Node 运行时：

```powershell
node scripts/backup-project-data.mjs
```

默认输出到仓库的 `backups/<UTC时间戳>-<随机后缀>/`，不会覆盖旧备份。也可以使用 `--output=E:/专用备份目录`；不能把输出放入被备份的资产目录。

目录包含 `database`、`r2`、`english`、`english-static`、`metadata`、`unclassified-assets` 和 `manifest.json`。数据库使用只读连接和SQLite Backup API，把已提交WAL内容纳入一致快照，不用主文件裸复制、不checkpoint原库。D1和R2所有SQLite（包括Miniflare metadata）均快照；R2二进制文件完整复制，并校验对象映射、文件存在与大小。WAL/SHM不作为恢复负载。

这是停写备份：检测项目服务和workerd进程，并在Windows以独占只读文件句柄检查SQLite/WAL/SHM是否被占用；无法检查或发现占用时拒绝。当前文件占用保护只支持Windows，其他平台明确拒绝执行备份/恢复写入。备份前后比对源文件SHA-256和WAL内容，源数据变化时任务失败。这些检查不能阻止备份期间人工启动新的任意写入工具，执行期间请保持项目停止且不要编辑数据。检测到无关workerd也会保守拒绝，不自动关闭用户进程。

校验包括每个负载文件SHA-256、SQLite integrity_check/foreign_key_check、所有表记录数和实际schema、R2映射对象及二进制大小、英语manifest、英语文件数。失败manifest标记failed并非零退出，不输出成功。manifest记录当前Git提交/dirty、迁移journal及SQL hash、实库schema；不会仅凭迁移文件名声称已执行。

备份不含AI缓存、构建缓存、依赖、临时文件、`.dev.vars`或`.env`。备份含私人题目和资料，应限制目录访问，并另行保存到独立设备；同一E盘的副本不能防硬盘故障。

## 校验与恢复

只检查备份，不写恢复目标：

```powershell
node scripts/restore-project-data.mjs --backup=E:/完整备份目录 --verify-only
```

首次验证应恢复到独立空目录：

```powershell
node scripts/restore-project-data.mjs --backup=E:/完整备份目录 --target=E:/codex/毕设探索/work/restore-check
```

不传target时目标为当前脚本所属仓库；backup必须显式指定。默认拒绝已存在业务数据或元数据的目标。校验manifest、文件hash、路径边界、重复路径、符号链接/目录链接、数据库和对象之后才准备恢复。

只有显式 `--force` 可恢复到已有目标，且必须先成功生成并验证当前目标的完整安全备份；部分/损坏目标无法产生完整备份时仍拒绝force。先在目标的 `.data-restore-*` 中准备文件，然后替换业务树；旧文件移到 `backups/pre-restore-files-*` 保留，发生异常尝试回滚，不递归删除原数据。准备期间目标变化也拒绝。恢复操作不是跨全部目录的系统级原子事务，断电时保留的安全备份和旧文件是恢复依据。

恢复后的空目录是数据验证副本，不是完整源码仓库。实际重新部署仍需保留/获取对应代码，手动配置密钥及真实D1/R2绑定。迁移器不得仅根据journal推断实库已执行哪些迁移，应检查备份中的实际schema。

本阶段不覆盖实际数据库。相关测试：`node --test scripts/project-data.test.mjs`，全部测试资产位于E盘工作目录work，使用合成数据库验证WAL、校验失败、防覆盖及force前备份。
