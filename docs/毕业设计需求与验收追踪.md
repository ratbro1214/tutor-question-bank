# 个性化数学辅导题库：需求与验收追踪

本文将当前系统功能映射到实现位置和可重复的验收证据，供开题、中期检查、测试报告及论文撰写使用。系统总体架构、数据模型和关键流程见 [`docs/系统设计说明.md`](系统设计说明.md)。需求编号在后续变更中保持稳定；新增需求应同步更新本表和测试记录。

## 项目边界

系统面向中学数学家教教师，管理学生、题目、教师确认分类、授课记录和复习追踪。学生知识点统计只描述已记录题目的分布，不直接推断学生掌握程度或学习效果。AI 输出是待教师确认的建议；教师可以在 AI 识别失败、不可用或结果不合适时独立完成题目分类和归档。

## 架构摘要

浏览器端使用 React 页面完成学生选择、图片预览与预处理、分类编辑和学习记录操作；Vinext API 路由负责请求校验和业务流程；Drizzle ORM 将结构化数据写入 Cloudflare D1，原题图片写入 R2；题目识别通过配置的 OpenAI 兼容接口调用视觉模型。数据库迁移保存在 `drizzle/`，可重复验收脚本和单元测试保存在 `tests/`、`scripts/`。

题目归档保存教师确认分类和来源字段：`live_ai`、`demo`、`manual` 或 `legacy`。人工归档时 AI 原始分类写为 JSON `null`，不复制教师分类冒充模型结果；旧记录用 `legacy` 表示创建时未记录来源。

| 编号 | 需求与验收条件 | 主要实现 | 验收证据 |
| --- | --- | --- | --- |
| FR-01 | 教师可以新增、修改和查看学生；已删除学生不出现在日常列表中 | `app/api/students/route.ts`、`app/api/students/[id]/route.ts` | API 集成验收：新增、更新、软删除和回收站恢复 |
| FR-02 | 教师可上传题目原图，查看预览，并可调整仅供 AI 识别的副本 | `components/upload-workflow.tsx`、`app/api/questions/route.ts` | 浏览器验收：预处理、原图保留、图片失败提示 |
| FR-03 | 系统可返回 AI 题干及分类建议；教师修改后的字段不能被迟到的模型结果覆盖 | `app/api/analyze/route.ts`、`components/upload-workflow.tsx` | 分类单元测试；浏览器并行编辑验收；`docs/performance-2026-09-27.md` 中的识别基准记录 |
| FR-04 | AI 失败后教师仍可填写题干、章节、题型、难度和知识点，并将确认结果归档；系统不得伪造 AI 分类 | `components/upload-workflow.tsx`、`app/api/questions/route.ts`、`db/schema.ts` | API 集成脚本验收 `classificationSource=manual` 且 `aiClassification=null`；浏览器人工归档验收 |
| FR-05 | 重复提交不得重复创建提问记录；相同原图由教师决定关联、另存或稍后处理 | `app/api/questions/route.ts` | API 集成验收：submission idempotency 和同图关联 |
| FR-06 | 教师可记录教学过程、复习计划和复习结果，并查询学生学习时间线与统计 | `app/api/students/[id]/learning/route.ts`、`lib/learning.ts`、`components/learning-panel.tsx` | `tests/learning.test.ts`；API 集成验收：教学、复习、结果、跨学生隔离 |
| FR-07 | 教师可查看题目分类、修改确认标签、查看原图并管理回收站 | `components/student-bank.tsx`、`app/api/questions/[id]/route.ts`、`app/api/trash/route.ts` | 分类校验测试；API 与浏览器主流程验收 |
| FR-08 | 教师可导出单个学生的结构化教学数据，并筛选日期范围；题目记录包含分类来源 | `app/api/students/[id]/export/route.ts`、`lib/xlsx-export.ts` | `tests/learning.test.ts`：工作簿结构、日期过滤及公式注入保护；API 集成验收人工来源 |
| FR-09 | 教师可为乘法公式试点题快速记录仅结果、部分过程或完整过程证据；证据不足时不强制确认错因，而是进入诊断队列；只有获得支持的具体错因进入可追溯画像 | `db/schema.ts`、`lib/learning.ts`、`app/api/students/[id]/learning/route.ts`、`components/learning-panel.tsx` | `tests/learning.test.ts`：仅答题卡快速记录、可选教师判断、诊断队列、画像状态转换及迁移兼容 |
| FR-10 | 教学智能体可基于真实作答生成两题诊断包；方案可保存、采用或放弃，采用后引导教师另行记录诊断作答，不得让 AI 方案直接成为画像证据 | `lib/teaching-agent.ts`、`lib/diagnostic-generation.ts`、`app/api/students/[id]/agent/diagnostics/route.ts`、`components/teaching-agent-panel.tsx` | `tests/teaching-agent.test.ts`、`tests/diagnostic-generation.test.ts`：克制决策、严格两题结构、无密钥回退、方案外键与独立留痕 |

## 质量需求

| 编号 | 质量要求 | 验收方式 |
| --- | --- | --- |
| NFR-01 | 无效章节、知识点或不完整教师确认分类不得入库 | 分类单元测试及 API 400 场景 |
| NFR-02 | 重复请求可安全重试；取消或失败不能清除用户已填写内容 | 同一提交编号重复归档测试；浏览器取消、失败和重试验收 |
| NFR-03 | AI 上游不可用时，系统仍可由教师完成核心归档流程 | 人工归档 API 与浏览器端到端验收 |
| NFR-04 | 题目图片与学生记录按学生归属读取；导出内容不得包含其他学生记录 | API 跨学生访问和 XLSX 导出隔离测试 |
| NFR-05 | 日志用于定位请求而不泄露 API 密钥、学生姓名、图片文件名或完整题目原文 | 审查失败/成功日志字段；不在日志中输出凭据和个人信息 |
| NFR-06 | 公开部署前必须限制学生数据访问范围 | **未完成**：当前是仅供本机预览的单用户系统，尚未实现登录、教师身份或租户级数据隔离；不得将当前版本暴露到公网或用于存放真实未成年人资料。需先确定部署身份模型，再为学生记录增加所有者并覆盖所有 API、图片与导出路由 |

## 毕设验收记录

本表不是测试通过声明。每轮验收后将日期、提交版本、执行命令、通过/失败数量、失败缺陷编号和浏览器人工验收结果追加到独立测试报告。AI 识别准确率和耗时报告应注明样本来源、标签真值、模型配置、失败样本及限制；只有真实测量值才可写入论文。阶段验收结果见 [`docs/验收记录-2026-09-27.md`](验收记录-2026-09-27.md)。

当前优先验收项：

1. 在测试数据库执行全部迁移，确认已有题目被标记为 `legacy`。
2. 用 AI 识别成功、演示模式和人工分类三种路径分别归档，核对题库来源标识。
3. 模拟 AI 返回内部错误，确认图片和手工输入保留，教师可以不重试 AI 而完成人工归档。
4. 执行分类、学习追踪、导出和 API 集成测试；将实际结果写入测试报告。
5. 按所在学院当届任务书与论文模板核对交付物、阶段报告和答辩要求。
